# CLM in Pascal

This directory contains the Free Pascal implementation of CLM and its test runner. The checked-in VS Code configuration builds a 64-bit Windows executable.

## Free Pascal Toolchain

The tested compiler version is Free Pascal 3.2.2. Download the compiler and target packages from the [official Free Pascal downloads page](https://www.freepascal.org/download.html). The [Windows x86_64 binaries](https://www.freepascal.org/down/x86_64/win64.html) are available there as well.

Make sure the compiler is available on `PATH`. In PowerShell, check the installation with:

```powershell
fpc -iV
where.exe fpc
```

The VS Code build targets Win64 x86_64 with `-Twin64 -Px86_64`. This requires the matching cross-compiler (`ppcrossx64`) and Win64 RTL/units. If FPC reports that it cannot find `ppcrossx64` or target units, install the cross-compiler and target packages that match your host compiler version. See the [Free Pascal cross-compilation guide](https://wiki.freepascal.org/Cross_compiling) for platform-specific setup. On Windows, confirm that `ppcrossx64.exe` is discoverable in the FPC installation:

```powershell
where.exe ppcrossx64
```

For Linux hosts targeting Windows, install the FPC cross-compiler and Win64 target units, plus the required Windows assembler/linker tools for your distribution. Keep the compiler, cross-compiler, and RTL package versions in sync.

## VS Code Setup

Open `src/pascal` as the workspace folder so the checked-in tasks resolve their paths correctly. Install:

- [Pascal](https://marketplace.visualstudio.com/items?itemName=alefragnani.pascal) for Free Pascal syntax highlighting, snippets, and language support.
- [CodeLLDB](https://marketplace.visualstudio.com/items?itemName=vadimcn.vscode-lldb) for the configured LLDB debugger. CodeLLDB supports compiled Pascal programs with compatible debug information. If its bundled LLDB is unavailable for your setup, install LLVM from the [LLVM releases page](https://github.com/llvm/llvm-project/releases).

## Build and Test

The default build task, **Build Free Pascal (debug)**, cleans and rebuilds `build/main.exe`. Run it with **Terminal > Run Build Task** or `Ctrl+Shift+B`. It invokes:

```powershell
fpc -Twin64 -Px86_64 -gw3 -gl -O- -Fuclm -Futests -FEbuild -FUbuild main.pas
```

The `-Fu` options add the CLM units and test units to FPC's search path. `-gw3` emits DWARF 3 debug information, `-gl` includes line information, and `-O-` disables optimization for debugging.

Run the test executable from this directory after building:

```powershell
.\build\main.exe
```

The runner executes the base, BPA, console, dictionary, ID, string, and storage suites. It prints results to the console and writes plain output to `main.log` in the current working directory. Each test run recreates the log.

## Debugging

The checked-in `.vscode/launch.json` configuration, **Debug Free Pascal (LLDB)**, builds the project first and launches `build/main.exe` in the integrated terminal. Select it in **Run and Debug** and start debugging. Breakpoints can use the DWARF and line information generated by the debug build task.

## Modules

- `clm/base.pas` defines CLM fixed-width types and geometry records.
- `clm/console.pas` provides console I/O and ANSI terminal helpers.
- `clm/bpa.pas` provides block and array storage primitives.
- `clm/dictionary.pas`, `clm/id.pas`, `clm/clm_string.pas`, and `clm/storage.pas` provide the higher-level CLM modules.
- `tests/` contains the test support unit and module test suites.

The string unit is named `clm_string` because `string` is a reserved Pascal identifier.
