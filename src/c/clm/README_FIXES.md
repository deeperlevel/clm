# CLM Serialization — regression fixes

This archive is based on the 15 headers supplied in `clm-serialization.zip`. Seven headers were modified: `string_format.h`, `string_json.h`, `string_dsv.h`, `string_ini.h`, `string_env.h`, `string_toml.h`, and `string_yaml.h`. All other original headers are unchanged.

## Changes

1. **JSON round-trip type preservation.** `clm_string_json_dumps` emits string leaves as quoted strings, and supported numeric/Boolean/null leaves as unquoted JSON literals. String contents such as `"true"` remain strings. This preserves JSON *types*, not necessarily identical source formatting or numeric spelling.
2. **Headerless DSV.** When `has_header` is `false`, the first record is data rather than discarded; the parser creates mapped columns named `column_1`, `column_2`, etc., from the first record and checks subsequent row widths. The generated names remain mapped in `clm_id` after a successful parse; registrations made by a failed parse are rolled back. Export without a header does not emit column names.
3. **Selectable conventional CSV quoting.** `clm_string_dsv_options` has a new `bool csv_quoting` member (defaults to `false` for backward compatibility). When `true`, quoted double quotes use `""`, backslashes are literal, and newline characters are allowed inside quoted fields. When `false`, the original CLM backslash escapes and single-quote handling are retained. Both serialization modes continue to quote every field.
4. **Opt-in automatic mapped-ID registration for tree formats.** All five tree codecs (JSON, YAML, TOML, INI, ENV) now offer `clm_string_<format>_loads_auto_ids(source_id, destination_id)` and `clm_string_<format>_load_auto_ids(filename_id, destination_id)`. These register previously unknown keys in `clm_id` and roll back only registrations created during a failed parse. Existing strict `loads`/`load` entry points are unchanged.

## Usage examples

```c
/* Headerless, RFC-style CSV with doubled quotes. */
clm_string_dsv_options options = {0};
options.has_header = false;
options.csv_quoting = true;
clm_string_dsv_loads_with_options(source_string_id, table_id, &options);

/* Import arbitrary JSON field names without pre-registering them. */
clm_string_json_loads_auto_ids(json_string_id, tree_id);
/* The generated names can be resolved using clm_id_try_get. */
```

## Validation

`tests/test_regressions.c` exercises typed JSON round trips, headerless DSV rows and generated columns, CSV quotes and multiline fields, original DSV escaping, strict-name behavior, auto-registration in all five formats, and rollback on JSON parse failure.

**Local verification:** 88 checks pass with GCC 14 and Clang in GNU C11 mode; 88 checks also pass with GCC AddressSanitizer + UndefinedBehaviorSanitizer. There are no warnings from this test translation unit with `-Wall -Wextra -Wno-parentheses -Wno-type-limits`. This is a targeted regression suite, not a complete format conformance suite.

The original archive does not include `file.h`, `path.h`, `platform.h`, or `gen.h`; CLM versions of those existing modules must be available for full-header compilation and testing. For the local tests, copies from previously supplied CLM sources were used. Avoid adding `-I .` to the command if it causes the project's `string.h` to shadow the C standard library `<string.h>`; use `-iquote .` instead.

```bash
gcc -std=gnu11 -D_GNU_SOURCE -Wall -Wextra -Wno-parentheses -Wno-type-limits \
  -iquote . tests/test_regressions.c -lm -o test_regressions
./test_regressions
```

## Compatibility notes

- Existing strict parser entry points retain their pre-registered-name requirement.
- The new `csv_quoting` field should be explicitly initialized when creating DSV options; zero initialization selects the original mode.
- Successful auto-ID registration affects the process-global `clm_id` registry. The registry remains globally managed by CLM, and autogenerated names are intentionally kept after successful imports.
- Parsing an invalid document attempts to remove newly created ID names. It does not remove ID mappings that existed before parsing.
